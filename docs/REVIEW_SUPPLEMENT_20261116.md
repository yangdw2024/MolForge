## 2. 总体判断

ChatGPT 的评价方向正确：现有多项修复具有可复现证据，但不能据此宣称所有功能完整正常。建议把当前状态写成：

> 基础建模、若干科学反例和交付完整性回归通过；原生交互、大体系主链路、真实外部计算、周期边界、干净环境安装及全部科研模块尚未完成验收。当前适合作为继续验收的发布候选，不是全功能生产认证版本。

另需澄清测试数量：112 项非原生 unittest 加 4 项 GUI 文件测试对应原记录的 116 项；134 项非原生 pytest 加同一 GUI 文件的 4 项对应原记录的 138 项。现有记录不支持“测试减少”的结论，两组测试仍存在重复覆盖，不能相加。

## 3. 必须补充的缺口

### P0-1：门禁名称和认证语义仍超出证据

当前构建器确实会在任一门禁失败后停止，但 `zero_mock_science`、`zero_crash_studio_isolation`、`bidirectional_fidelity` 仍全部由同一个 `gate_summary["all_passed"]` 派生。它们不是三项独立认证。

与此同时，HPC 测试明确使用 mock runner，Multiwfn 门禁主要验证样例文本解析。因此“15 项回归通过”可以成立，“zero mock science 已认证”不能由这些结果推出。

验收要求：

1. 报告先只写 `regression_suite=PASS` 和逐项测试结果。
2. 每项高级认证必须有独立测试、独立证据和独立通过条件；未执行时写 `NOT_TESTED`，不能写 `PASS`。
3. 区分 mock、样例解析、真实外部程序和真实桌面操作，禁止混用通过率。

### P0-2：大体系低内存/60 FPS 仍不是主工作台能力

当前源码检索中，`MassiveSystemData`、`SpatialGridIndex`、`InteractionAdaptiveController` 的生产引用仍只出现在领域模块定义和导出，实际调用位于对应测试；没有证据表明 PDB 导入、主文档、VTK 主视口已经接入这套数据路径。

百万原子测试主要验证扁平数组、采样、查询和预算状态机；“一亿原子约 1.2 GB”是坐标与元素数组的理论推算，不包含拓扑、ID、选择、命令、撤销和渲染数据。“80k 点预算”也不是实测 60 FPS。

验收要求：

- 在结论中保留“独立数据结构试验，未证明主 GUI 支持一亿原子或 60 FPS”。
- 只有主工作台真实加载、旋转、选择、编辑、撤销和长时间运行的数据才能支撑大体系宣传。

### P1-1：显式三重态已修复，但未知自旋仍被显示成确定结论

当前信息栏优先读取显式 `multiplicity`，这是有效修复；但未提供该属性时，仍按电子数奇偶显示 Singlet/Doublet。奇偶性只限制可能的多重度，不能确定实际电子态。

建议：

- 未指定时显示“未指定”或“默认假设：单重态/双重态”，不要显示为已测定的基态。
- 区分“计算输入默认值”和“分子真实电子态”，并补充无显式多重度 O2 的反例测试。

### P1-2：点群问题不能只写“近似”，还应加入明确反例

当前逻辑是近平面显示 Cs，否则显示 C1。除了旋转和阈值问题，还应加入：

- 线性分子：不能因 SVD 厚度很小就显示 Cs。
- 非平面高对称分子：例如甲烷不能因为非平面就显示 C1。
- 近平面但不对称、 Exact planar、高对称和阈值附近结构。

在真正对称性算法接入前，建议界面分别显示“平面性估计”和“点群：未计算”，不要把平面性标签当点群结果。

### P1-3：可旋转键需要公开统计口径

当前实现已经排除环内键，并使用重原子、单键、非芳香和端点邻居条件；这仍不必然等于 RDKit 的严格可旋转键定义，尤其涉及酰胺等受限旋转键。

建议界面和报告注明“自定义非环单键计数”或采用明确的 RDKit 描述符，并用咖啡因、酰胺、环内键、末端键及多连通分量做对照。两种口径可以不同，但不能都 unnamed 地称为同一个标准描述符。

### P1-4：CRYST1 只证明字段导入，未证明 PBC 功能

还需单独验收：晶胞显示、跨周期边界成键、最小镜像距离/角度、周期选择、CRYST1 导出回读，以及 MD 盒子的实际使用。字段存在不能代替这些结果。

### P1-5：交付 ZIP 完整性不等于可安装、可启动

现有 ZIP 哈希回读和无嵌套 ZIP 是有效证据，但还缺：

1. 从交付 ZIP 解压到不含源码的新目录，使用干净环境安装依赖并启动。
2. 从 wheel 安装到干净环境，验证入口、资源文件和版本号。
3. 完成一次打开、编辑、保存、关闭、重开。
4. 记录依赖版本和安装日志；不能用开发机已存在的包掩盖缺依赖或漏打包资源。

### P1-6：真实外部链路仍未验收

本轮没有真实 Gaussian、Multiwfn、GROMACS/HPC、LLM 请求，也没有逐项验证所有导出格式。建议每个外部引擎至少完成一个小型真实端到端样例，记录输入、可执行文件版本、单位、退出状态、输出文件和独立参考值；另测失败、超时、取消和结果回读。HPC mock 测试继续保留，但单独标为协议/逻辑回归。

### P1-7：凭据清理结论需要收窄

当前证据只支持“所检查的默认 `api_key` 赋值没有发现非空字符串常量”，不支持绝对化的“全链路无密钥泄漏风险”。还应对当前源码、ZIP、wheel、配置和可访问历史发布物做秘密扫描；若历史密钥真实有效，应吊销/轮换。不要为了验证而把密钥发送到外部端点，也不要在报告中打印密钥。

### P1-8：32 万原子只完成解析探针，且存在重复序号边界

本次 5.49 秒是与其他测试并行时的单次解析耗时，不是 GUI 加载时间。输入还存在 31,300 个重复序号 token，因此后续测试不能只依赖 PDB serial 作为身份。

真实桌面验收至少覆盖：加载总耗时、峰值内存、首帧、旋转 P50/P95 FPS、选择、删除、撤销、编号映射、保存后重开，以及重复 serial 下内部 AtomId 是否始终稳定。性能测量应在无其他重负载任务时串行重复运行，并保留原始样本。

### P1-9：保存与数据安全不能只验证“测试不再弹窗阻塞”

GUI 测试中的对话框模拟只能证明测试可控，不能证明真实保存链路。需要真实桌面覆盖：新建、修改、保存、另存为、未保存关闭提示、取消关闭、保存后重开、撤销/重做，以及异常退出后的数据保护。文件回读还应检查坐标、键级、芳香性、形式电荷、多重度、立体化学和晶胞字段是否保持。

### P2-1：原生视觉验收应形成矩阵

除 22 px 的 960×774 离屏反例外，真实桌面还应覆盖 100%/125%/150% DPI、常用分辨率、双屏、字体切换、编号开关、鼠标绘制、拖拽旋转和保存。截图服务失败时，应把该项保留为 `BLOCKED/NOT_TESTED`，不能转为通过。

## 4. 推荐下一轮顺序

1. 先修正门禁报告语义和大体系宣传边界，确保“通过”本身可信。
2. 修未知自旋和点群展示，明确可旋转键口径。
3. 完成真实桌面保存、绘制、旋转和 DPI 矩阵。
4. 串行完成 32 万原子主 GUI 性能与稳定性验收，再讨论更大体系。
5. 完成 CRYST1/PBC 和至少一条真实外部计算链路。
6. 最后从 ZIP 与 wheel 各做一次干净环境安装验收，再更新发布结论。
