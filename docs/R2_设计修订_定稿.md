## 一、先说实话：7 份草稿文档的问题

这 7 份文档是昨晚一晚上连续写出来的，方向感对，但**不能直接照着开工**，原因如下。

### 1. 文档之间互相打架，没有定论

| 争议点 | 文档 A 说 | 文档 B 说 | 实际要选哪个 |
|---|---|---|---|
| 3D 渲染引擎 | PyVista (VTK) | Mol* (WebGL2) | **PyVista**（理由见下文） |
| 2D 绘制 | QGraphicsView 从零自绘 | RDKit.js / Web 组件 | **先不做交互式绘制**，一期走 RDKit 渲染 |
| 前端外壳 | 纯 PyQt6 | PyQt6 + QWebEngineView + React | **纯 PyQt6** |
| 包名 | MolForge | molecular_editor/ | 统一为 **MolForge** |
| "你只需要写 Python" | 文档 1/3/6 | 文档 4 又说"要学 React/TS" | 以"只写 Python"为准，不引入前端工具链 |

同一份报告前面推荐 PyQt6，后面又说"最好看的全是 Web 技术栈"要上 React，自相矛盾。

### 2. 严重低估了 2D 分子编辑器的工程量

文档里写"阶段 1 一周搭 2D 画布，画原子画键"。这是**最大的认知错误**：

- 一个 ChemDraw 级别的 2D 编辑器（画单键/双键/三键、楔形键、自动规整、价态检查、立体化学、连续画键、擦除、撤销）是**几万行 C++** 的工程量，ChemDraw 公司做了 30 年。
- 用 PyQt6 的 QGraphicsView 画几个圆和直线容易，但做到"化学上正确、可编辑、自动规整"是另一个量级。
- 研究生业余时间从零写，3 个月都未必能画出一个能用的键线式。

**结论：一期绝对不从零写 2D 编辑器。**

### 3. 几个"参考项目"核实结果（联网查证）

| 文档里提到的项目 | 真实情况 | 对我们的意义 |
|---|---|---|
| MoleditPy 1.14.1 (2025.11) | **真实存在**，作者 HiroYokoyama，最新 2.8.0a2 (2026.03)，PyQt6+RDKit+OpenBabel，LGPL，已有插件架构和 Gemini AI 插件 | 可以参考它的结构，但不直接魔改（协议 LGPL 有传染性） |
| Ketcher 2.20.0 / 3.3.0 | **真实存在**，EPAM 开源，最成熟的 Web 2D 分子编辑器，纯 JS/TS，可嵌入网页 | 二期做交互绘制时优先嵌入它，不要自己写 |
| megane-viewer 0.18.0 | **真实存在**，Rust+React，15 小时前还在发版，但它是 **3D 查看器不是 2D 编辑器** | 3D 渲染可参考，但不引入 Rust 工具链 |
| schematic (pure-Rust RDKit 替代) | **真实存在**，但还在 0.x 早期，功能远不如 RDKit | 不采用，继续用 RDKit |
| Avogadro 2.1.0 | **2026-10-23 刚发布**（4 天前），C++/Qt6 完整分子编辑器 | 可下载来当 UI 参考，不作为我们的底座 |
| RDKit 最新版 | **2026.9.1**（2026-10-09 发布），不是文档说的"2025.3+" | 用最新版 |

### 4. 夸大宣传要剔除

- "几万原子 60fps PBR+AO"：Mol* 自己都跑不动这个量级，OSC 小分子根本不需要。
- "AI 直接 draw_atom(x=100,y=200)"：AI 画分子应该输入 SMILES 或"画一个阿司匹林"，不是像素坐标。这个 API 设计不现实。
- "碾压 GaussView"：GaussView 6 是 2017 年的老软件，颜值确实过时，但它的 2D 编辑交互经过 10 年打磨，我们不要在宣传上对标，先把工具做能用。

## 二、定稿技术选型

### 核心原则

1. **你只写 Python**，不引入 React/TypeScript/npm/WebGL 工具链。
2. **不重复造轮子**：2D 绘制和 3D 渲染都用现成库，不自己写渲染引擎。
3. **base 环境直接用**：你的 conda base 已经装好了 rdkit + PyQt6 + fastapi，不需要新建环境。
4. **一期先跑通一个能用的工具**，不是先追求"碾压 GaussView"。

### 技术栈（最终版）

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | Python 3.13 | 你已经会，base 已装 |
| GUI 框架 | **PyQt6** | base 已装，QGraphicsView/QMainWindow/QWebEngineView 都有 |
| 化学计算引擎 | **RDKit 2026.9.1** | base 已装，行业标准 |
| 2D 渲染（一期） | **RDKit 自带 rdDepictor + Draw.MolToFile**（SVG/PNG） | 导入 SMILES/SDF → 自动生成 2D 坐标 → 渲染成图，不做交互式绘制 |
| 2D 绘制（二期） | **嵌入 Ketcher**（QWebEngineView 加载本地 Ketcher bundle） | 最成熟开源 Web 编辑器，不自己写 |
| 3D 渲染 | **PyVista + pyvistaqt**（基于 VTK，Python 原生） | 不用学 WebGL，开箱即用，球棍/CPK/表面都有 |
| 文件格式 | MOL/SDF/SMILES/GJF/XYZ/CUBE | RDKit + OpenBabel（ztop 环境有 openbabel，必要时补） |
| AI 接口（一期） | **同进程 Python API**（直接 import） | 最简单，不起 HTTP 服务 |
| AI 接口（二期） | **FastAPI + uvicorn** | base 已装，给未来接 LLM/远程用 |
| 打包 | PyInstaller onedir | 和你 Gaussian 插件一样的流程 |
| 配色 | GitHub Dark 深色主题 + CPK 标准配色 | 文档 5 的 CPK 表可用，但 F/Cl 的荧光绿调成更柔和的色值 |

### 为什么不选 Mol* / 3dmol.js（WebGL 路线）

文档 4/6 推荐 Mol*，理由是"颜值高、PBR、软阴影"。但：

- Mol* 是 TypeScript 写的 Web 组件，要用它就得引入前端构建链（npm/vite/React）。
- 你 Python 基础薄弱，同时学 Python + PyQt6 + RDKit + React + WebGL + QWebChannel 桥接，学习成本爆炸。
- PyVista 是 VTK 的 Python 绑定，`pyvista.plot(molecule, style='ball+stick')` 一行代码就出 3D，效果对 OSC 小分子完全够用。
- 颜值不够，后期可以换 Mol* 嵌入，但一期先用 PyVista 把工具跑起来。

### 为什么不直接魔改 MoleditPy

- MoleditPy 是 LGPL-3.0 协议，如果你基于它改并分发，你的衍生代码也必须 LGPL 开源。
- 它是日语作者写的，文档以日文为主，中文/英文资料少。
- 但它的插件架构、菜单注册方式值得参考（见 docs/调研/MoleditPy 插件手册要点）。

## 六、和 GaussView 的真实对比（不吹）

| 维度 | GaussView 6 (2017) | MolForge（目标） |
|---|---|---|
| 2D 编辑交互 | 成熟，打磨 10 年 | 一期只读，二期嵌 Ketcher 后追平 |
| 3D 渲染 | 老 OpenGL，无 AO/PBR | PyVista(VTK)，球棍/CPK/表面，够用 |
| 接 Gaussian | 原生集成 | 通过你已有的 gaussian-dsh-plugin 后端 |
| AI 集成 | 无 | 有（二期） |
| 颜值 | 2010 年代风格 | 深色现代主题 |
| 跨平台 | 仅 Windows | PyQt6 天然跨平台 |

**我们的定位不是"碾压 GaussView"，而是"一个给 OSC 科研用的、长得好看、接 Gaussian 顺手、带 AI 的轻量工具"。**
