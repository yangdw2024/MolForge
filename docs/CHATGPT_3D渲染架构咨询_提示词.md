# 分子工作台 3D 渲染架构与工具选型咨询

## 项目背景

我在做一个 **AI-native 分子工作台**（Python 桌面应用），目标用户是计算化学研究生。核心痛点是：ChemDraw / GaussView 这些传统软件**不能接 LLM API**，不能当 AI 的"化学眼睛"。我要做一个让 LLM 能直接操作分子、提交计算、解析结果的工具。

## 当前技术选型

- **语言**：Python 3.13
- **GUI**：PyQt6
- **化学核心**：RDKit（分子数据模型、SMILES、MOL/SDF 读写）
- **3D 渲染**：PyVista 0.49.1 + VTK 9.7.1 + pyvistaqt
- **2D 渲染**：RDKit MolDraw2D + cairosvg（SVG→PNG）
- **架构**：分层（core / io / render / ai / ui），Molecule 一等公民数据模型

## 当前问题（紧急）

**3D 渲染质量极差**。我用 PyVista + VTK 9 的 PBR 材质（metallic/roughness）+ 环境光 + 抗锯齿 + 深度剥离，做出来的 3D 分子图**跟 GaussView 比都差得远**，更别说跟 PyMOL / ChimeraX / VMD 比。具体问题：

1. 材质塑料感强，没有真实的光照反馈
2. 没有环境光遮蔽（AO），物体之间没有阴影
3. 没有全局光照（GI），暗部死黑
4. 后处理完全没做（没有 bloom、色调映射、FXAA/TAA）
5. 球棍模型看起来像玩具，不像科学可视化

## 目标

1. **3D 渲染要达到 PyMOL / ChimeraX / VMD 级别**（电影级科学可视化）
2. **2D 渲染要在颜值上完爆 ChemDraw**（化学精确性是另一回事，先把颜值做上去）
3. **支持 256MB 分子文件打开不卡**（几十万到几百万原子，MD 轨迹/蛋白级别）
4. **架构干净**：不要一个 main.py 几万行硬编码，要分层、可扩展
5. **能接 LLM API**：LLM 通过 function calling 操作分子（查看性质、导出文件、提交计算）
