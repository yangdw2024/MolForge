# MolForge 修复经验记录

## 2026-11-16：测试发现数与路径必须先核实

- 本轮基线发现 116/138 中各有一项 GROMACS 测试失败，根因是测试假设 `powershell.exe` 必在 Conda 子进程 PATH 中。修复为使用 SystemRoot 下的绝对路径，未删除或跳过测试。
- 定向测试时误用了不存在的旧测试文件名，unittest 返回 0 项。后续所有门禁必须解析实际执行数，0 项立即失败，不能只看进程退出码。
- 修改源码前必须先 Read 当前精确片段；历史报告中的变量名和行号可能已变化，不能凭旧片段反复 Edit。
- 晶胞反例必须计算是否真的退化：10°/10°/10° 并非零体积，真正共面的 120°/120°/120° 才可用于该反例。修正的是错误测试，不放宽产品校验。
- 当前 Conda 的 Qt offscreen 字体族枚举为 0，离屏截图方框只能证明无字体环境，不能用来判定原生中文显示；视觉验收必须在原生 Windows Qt 上完成。
- 双原子场景不能用通用三原子相机分支；需要 0/1/2/≥3 原子统一适配，且双原子视角不能完全沿键轴。自动适配只应在最初几个原子出现时触发，不能每次编辑重置用户视角。
- wheel 的 `packages.find = ["molforge*"]` 不会自动包含顶层 `main.py`；`project.scripts = main:main` 必须同时显式配置 `py-modules`，并用隔离安装实际执行入口验证。
- 科学工作流中的资源默认值也要审计：IGMH 曾硬编码 24 核/24GB，与本机 8 核/12GB 约束冲突。默认资源与测试断言都应进入代码审查。
- ORCA 多进程运行依赖 `mpiexec`；可执行文件存在不等于并行链路可用。本机改单进程可完成真实计算，但必须单独保留 MPI 未配置结论。
- GROMACS 三个版本都能执行 `--version`，但多个版本在写任何输出文件时失败。版本输出和读取输入不能作为 MD 任务成功证据，也不应反复以相同命令消耗轮次。
